# Grand Strand Systems
## Summary
Grand Strand Systems is a software engineering company that focuses on developing and testing backend services. A client who has employed the company requested the development of a mobile application with functioning contact, task, and appointment modules. Alongside the program, a suite of unit tests has been created to ensure the customer's requirements are met.

## Final Thoughts
When creating functional code, security measures should be implemented from the beginning and throughout development instead of waiting until the end of the software lifecycle. For example, anything that requires input from the user should be validated in the moment. By doing so, errors and exceptions can be caught earlier instead of the application crashing due to an unexpected error. This also improves reliability as the inputs are already expected to stay within their limits. By implementing validation techniques, tests can then "hook" onto the errors that may arise. Being able to assert expected outcomes is useful in pinpointing issues that exist in the codebase and validating the sections that are functioning correctly. Alongside the tests, the coverage report that the test framework provides is immensely useful in highlighting lines of code that are unaffected by the current tests.

Many user needs are extrapolated from the software requirements and then incorporated into the program. To refine the details, gathering methods like surveys and one-to-one interviews are conducted to strengthen the outlined requirements. Upon analyzing the requirements, constraints are formed to define the boundaries of what the program should and can do. The validation techniques and tests are then based on the established limits.

When designing software, it starts with analyzing the functional requirements set by the client and forming nonfunctional requirements that describe how the program would meet the customer's needs. Thorough documentation sets the tone of how development proceeds, as it acts as the blueprint for success. Once the planning and design phase has finished, development can begin. Tests should be created alongside building the codebase to ensure the code is being verified along the way. To improve quality and adaptability, features should be broken up into smaller, more manageable components. Sole focus on one aspect makes development and testing easier. When the time comes, integration and systems tests can be conducted to see how the software works as a whole.
